# Сессия 2026-10-18, № 01 — Организация разработки

## Источник и пределы сводки

Запись составлена по организационной переписке. Это сводка существенного контекста, а не дословный экспорт. Другие чаты и реальный Unity-репозиторий здесь не аудировались.

## Цели и предпочтения владельца

- Разрабатывать мобильную игру SpaceSortingGame с помощью Codex: менять не только скрипты, но также сцены, объекты и игровой интерфейс Unity.
- Разделять обсуждения геймдизайна, организацию и непосредственную разработку.
- Предпочитать локальную разработку; продолжать её на двух компьютерах.
- Использовать уже существующий GitHub-процесс для переноса файлов игры.
- Сохранять контекст обсуждений, чтобы на второй машине Codex понимал причины решений и предыдущие шаги.
- Подготовить полный комплект документов, который владелец скопирует в Unity-проект.

## Состояние подключения со слов владельца

Unity MCP установлен. Пользователь привёл сообщение:

Также сообщалось о настройке локального сетевого доступа. Фактическое соединение с редактором не проверено. На втором компьютере конфигурацию и зависимости нужно проверять отдельно.

## Обсуждённые варианты

- Для регулярной разработки рекомендован GPT-6.1 Sol; для сложных решений рассматривалась Astra. Это рекомендация из обсуждения, а не требование к модели и не гарантия будущей доступности.
- Рассматривался бесплатный Claude для второго мнения по архитектуре. Решение о его обязательном включении не принималось. Можно передавать ему сводку и нужные файлы; не считать его автоматически знакомым с проектом.
- Обсуждалось продолжение чатов через веб. Для выбранного процесса решено не зависеть от переноса локальной истории: хранить письменную память в репозитории.
- Обсуждались режимы подтверждений и возможность запрашивать разрешение перед каждым действием. Это было выяснение возможностей, а не распоряжение включить такой режим.

## Принятые решения

- ORG-001: локальная работа на двух компьютерах с передачей через GitHub.
- ORG-002: описание игры, журнал решений, краткая передача и записи сессий как память проекта.

## Изменения и проверки

- Подготовлены AGENTS.md и комплект Docs, инструкция по установке и передаче.
- Исходный GAME_DESIGN_CONTEXT.md использован как справочный материал; синхронизированный оригинал не менялся.
- Изменения подготовлены вне настоящего Unity-проекта. Проверки игры не выполнялись.

## Продолжение

Сначала скопировать документы и выполнить аудит проекта и подключения. При переносе между компьютерами сохранять изменения, отправлять их в GitHub и получать их на другой машине до начала новой работы. Не редактировать одинаковые сцены одновременно.
